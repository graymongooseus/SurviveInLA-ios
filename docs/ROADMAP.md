# 开发路线图

## 代码量预估

| 阶段 | 可交付结果 | Swift 生产代码 | 测试代码 | 内容数据 |
|---|---|---:|---:|---:|
| 垂直切片 `0.1` | 地图、市场、买卖、移动、利息、事件 | **997 行（当前实测）** | **67 行（当前实测）** | 6 地点、8 商品、6 事件 |
| iOS 基础版 `0.2` | 10 地点、银行、还债、诊所、仓储、日记、结算 | **1,518 行（当前实测）** | **115 行（当前实测）** | 10 地点、8 商品、6 占位事件 |
| 可玩 Alpha | 自动存档、引导、内容扩展与平衡 | 2,500–3,500 行 | 400–700 行 | 10 地点、12 商品、40–60 事件 |
| 内容 Beta | 完整 40 天节奏、难度、音效、引导 | 4,500–6,500 行 | 800–1,200 行 | 100–150 事件、8–12 结局 |
| App Store `1.0` | 无障碍、本地化、分析、发布流程 | 6,000–9,000 行 | 1,200–1,800 行 | 中文与英文内容包 |

内容文案和 JSON 不计入 Swift 代码量。若首版加入账号、云同步或联网排行榜，通常还会增加约 1,500–3,000 行客户端代码，并引入服务端维护成本，因此暂不纳入主线。

## 里程碑

### M0 · 垂直切片

- [x] SwiftUI + MapKit 工程
- [x] 地图优先主界面
- [x] 五种商品的每日市场
- [x] 买卖、现金、库存容量和平均成本
- [x] 移动、利息、随机事件与确定性测试
- [ ] 真机体验反馈

### M1 · 完整单局

- [x] 10 个洛杉矶旅行地点
- [x] 银行存取款与还债
- [x] 背包总览和平均成本
- [x] 医院治疗与仓储升级
- [x] 第 40 天强制结算、评分与重新开始
- [x] 健康归零失败流程
- [x] 生存日记
- SwiftData 自动存档
- 20–30 个基础事件

验收标准：玩家可以从第 1 天完整玩到结局，不需要开发者工具介入。

### M2 · 洛杉矶内容化

- 确定作品语气与目标受众
- 扩展地点、商品和事件
- 区域价格特征与事件前兆
- 交通成本、时间和风险差异
- 新手引导与第一局保护

验收标准：三局游戏产生明显不同、但能解释的策略路径。

### M3 · 体验打磨

- 日记与历史价格
- 动效、触感和音效
- Dynamic Type、VoiceOver 与高对比度
- 中英文内容
- 难度和平衡测试

### M4 · 发布

- App 图标、商店截图与隐私说明
- GPL-2.0 声明、原作者署名和对应源码发布方式
- TestFlight 测试
- 崩溃监控与最小化匿名分析
- App Store 审核与 `1.0` 发布

## 我们的协作节奏

每轮只推进一个可玩的机制：

1. 你决定题材、语气和数值取向，并试玩上一轮。
2. 我实现规则、界面和测试，提供模拟器截图与变更摘要。
3. 你反馈“哪里不好玩或不像洛杉矶”，不需要描述技术方案。
4. 我调整并把确认过的规则写入文档和自动测试。

下一轮建议先做 SwiftData 自动存档，再由你逐批确认洛杉矶事件文案。核心规则和内容数据保持分离，修改事件不需要重写界面。
